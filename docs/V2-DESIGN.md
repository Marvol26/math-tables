## 2. Batch 0 — fixes (decisions)
- **B1 charts (revised — per-mode series, not mixing).** `Stats.trends(state, n)` returns, over one common window of the last n sessions (all modes): `coins` and `masteredCount` as today (all-mode), and `accuracy`/`avgMs` as **per-mode series** `{ typed:[…|null], falling:[…|null], tetris:[…|null] }` aligned to the same x-axis (null where that session is another mode). `lineChartSvg` gains multi-series support (one colour per mode, a legend line `T.parent.modeLegend`, nulls break the line). Rationale: Marat's complaint is "frozen at round 4"; a per-mode chart on a shared axis is neither frozen nor mixes a 25 %-guess-floor recognition mode into typed recall (FALLING F9's reasoning survives as separate lines instead of a filter). Tests: window alignment, nulls, a run of 30 falling sessions leaves the typed line with gaps, not blanks.
- **B2a — one-time evidence rebuild (revised).** `Migrate.rebuildEvidence(state, now)`, called from the boot migrate path (schema 1 → 2, see step 4), guarded by `state.meta.evidenceRebuild = { done:true, at, reason }`:
  1. **Preflight**: every session carries an `attempts` array (none trimmed by retention); every non-retry attempt in `sessions[].attempts`, `active.attempts`, and each parked journal's `attempts` validates as `{ key ∈ Facts.allKeys(), asked canonical for key, ok boolean, ms finite ≥ 0, t finite > 0, retry boolean, interrupted boolean }`; **source integrity**: every completed session has finite `startedAt ≤ endedAt`, each of its attempts satisfies `startedAt ≤ t ≤ endedAt` and `key ∈ planned` (canonical); **the multiset of its non-retry attempts equals `planned` exactly (one first attempt per planned fact, no duplicates, none missing)**; `firstTryCorrect` equals the count of those with `ok`, and `misses` equals the set of those without `ok` (order-insensitive); `active`/parked journals satisfy `t ≥ startedAt` for every attempt and **`canonical(non-retry attempts) ⊎ canonical(queue) == canonical(planned)` exactly** (disjoint union, no duplicates, no overlap; the painted `current` question is still in `queue`, so no exception is needed). The same invariants are added to `validateImport` (backward-compatible: sessions without `attempts` pass). Any failure → **no change to facts/map/sessions**; the guard records `{ done:false, reason }` and the preflight re-runs on the next boot (cheap, O(attempts)); `reason:"trimmed"` (sessions older than retention have no attempts — can never become safe) sets `done:true`.
  2. **Timeline replay**: build a fresh `facts` by replaying all validated non-retry attempts in `t` order (ties by session order); at each completed session's `endedAt` snapshot `masteredAfter` and rewrite `session.masteredAfter`; recompute `stationsReached` per session at its finish boundary and rewrite `session.stationsReached` and `map.reached[n] = endedAt of that session`. `map.reached` is rebuilt from scratch and **stations are evaluated only at completed-session boundaries**: `active`/parked attempts feed `facts` (so the live view is right) but never reach a station — that happens, as always, when their session finishes. No "assign at `now`" fallback.
  3. **Commit** — the rebuild produces a *candidate* state; it is adopted (assigned to `App.storage.state`, rendered) **only after** the boot CAS save of the candidate succeeds. On save failure the original loaded state stays byte-identical and the app runs normally on it (it is self-consistent; play is not blocked), the guard stays `done:false`, and the next boot re-runs the deterministic, idempotent rebuild — which then also includes whatever was played meanwhile.
  4. **Schema**: `SCHEMA_VERSION` 1 → **2** in this batch (`meta.evidenceRebuild` must not be silently dropped by an older client rebuilding the state object; an older cached client refuses schema 2 with the existing `schemaTooNew` message, which is the safe outcome). Migrate 1→2 = add `meta`, canonicalise `economy.unlocked` (§3.4). `validateImport` accepts schema ≤ current.
  Tests: a 29-session typed+falling fixture with 5 attempts in `active` and 4 in a parked journal rebuilds facts identical to live play; `masteredAfter` history is rewritten to the correct per-session values; stations land on the right session; second boot is a no-op; malformed attempt → untouched + `done:false`; trimmed → untouched + `done:true`; import of an old backup → same path.

## 4. Batch 2 — Rectangle Tetris ("מגדל המלבנים 🧱", mode `"tetris"`) — revised
### 4.1 Idea
The fact `a×b` is a rectangle falling into a well of `CONFIG.TETRIS.COLS = 10` columns × `ROWS = 14` rows. The piece IS the area model already used in the wrong-answer helper; completing rows rewards fitting `3×4` beside `7×4` — the distributive idea behind the strategy hints.
### 4.2 Round (deterministic phase machine — pure `Tetris` section in core.js)
`active.tetris = { grid, phase, x, w, h, deadline, rowsCleared, rowBonus }`. Phases: `falling → (landed) → answered → placed`.
- On paint: `w = a, h = b` **as asked** (the asked direction gives the orientation, so `7×4` and `4×7` are different pieces); `x` centred; `deadline = shownAt + durationSec·1000`; one journal save (as today's paint).
- **Placement control (iPad-first):** tap a column of the well → the piece moves so its left edge is that column (clamped); ◀ ▶ buttons + arrow keys also move it. Moves are **UI-local** (no save per tap); `x` is persisted only with the answer.
- **Answering:** tap one of N option bubbles in a static row above the well (`Falling.candidates`; keys 1–N). The answer event carries `x`; the reducer places the piece immediately in the same `submit()` mutation, in this order: compute the landing row; **if the piece cannot fit → reset the well and recompute the landing in the fresh well (the triggering piece is placed there, never discarded)**; then `place`; then `clearFullRows` — **one save**, idempotent by question. Answer before `deadline` ⇒ ×2 (`withinLimit` exactly as falling). After the deadline the piece visually rests at the bottom (`landed`), still answerable with no ×2, still movable — landing never places anything.
- **Wrong tap:** dot-picture + הבנתי as everywhere; the piece is placed **grey** at its `x`; the fact is re-asked at the session end. **Retry placements are tainted** (third cell colour, "retry"): any row containing a grey or retry cell clears normally but pays 0 — `_rows` derives only from first-attempt correct placements (I1 holds; test: deliberate miss on 10×10 then correct retry mints nothing).
- **Overflow:** piece cannot fit ⇒ well resets (`T.tetris.wellReset = "הקיר התמלא — מתחילים קיר חדש! 🧱"`), never a penalty; happens inside the same reducer step.
- **Resume:** the suspended question is deferred (F10); the well grid persists; a deferred piece is re-asked later as interrupted (no ×2) with `x` re-centred.
- **CSS is a projection only**: the fall is a `top` transition to the landed position; `transitionend` only toggles the visual `landed` class; the source of truth for ×2 is `deadline` in core.
### 4.3 Coins
`ROW_CLEAR_COINS = 1` per fully first-attempt-coloured row, `MAX_ROW_BONUS_PER_SESSION = 20`, ledger `l_<sid>_rows` appended in `finish()` before `newUnlocks()`. Counts for mastery/map like balloons; carryover off. `Stats` per-mode series get a `tetris` line (B1). Summary suffix 🧱; parent history 🧱.

### 4.6 Feasibility gate — simulator BEFORE implementation (Codex #6)

## 7. Structure batches (Codex gpt-5.6-sol / high read-only review, 2026-08-28; verdict = split, no per-screen modules)
### 7.1 Batch S1 — deploy contract (first, smallest)
- Asset URLs carry **content hashes**: `core.js?v=<sha1[0:10] of file>` etc., for every local CSS/JS asset (`core.js`, and after S2 `styles.css`, `strings.js`, `app.js`). `tools/bump-version.js <x.y.z>` (Node, stdlib) sets `APP_VERSION`, rewrites every hashed URL in `index.html` and `sw.js`, and derives the SW cache name from `APP_VERSION`. Not a build step: files are served as-is; the tool only edits the two files that reference assets.
- **Release fingerprint** for the unversioned entry points: `sw.js` holds `RELEASE = "<APP_VERSION>-<fp>"` where `fp` = sha1[0:10] over the contents of `index.html`, `manifest.webmanifest`, `icon-180.png`, `icon-512.png` (in that order, after the hashed URLs were written); the cache name is `RELEASE`. Tool order after S2: set `APP_VERSION` in `app.js` → hash `core.js`, `strings.js`, `app.js`, `styles.css` → rewrite their URLs in `index.html` → compute `fp` → write `RELEASE` into `sw.js`. (Before S2 the same with `index.html`'s inline script.)
- `tests/deploy-contract.test.js` (in `npm test`): recomputes each asset's hash and the fingerprint and asserts every reference in `index.html` and `sw.js` `PRECACHE_URLS` and `RELEASE` matches (**any changed deployable file — asset, `index.html`, manifest, icon — without running the tool fails the suite; this is what catches the recorded 2026-08-27 incident, which the old three-place bump could not**); every hashed asset is precached with `cache:"reload"`; no unversioned duplicates; classic scripts in exact order `core.js, strings.js, app.js` with no `async`/`defer`; `index.html`, manifest and icons are precached unversioned under the fingerprinted cache. CLAUDE.md rule 7 and README rewritten around tool + test.
